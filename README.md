# vpsFocus FAQ

A static FAQ site that accompanies [vpsFocus](https://vpsfocus.xyz) — analytics and monitoring for websites on your own VPS. It is built to be read by people **and** by AI agents and search engines, so they can get accurate, citable answers about the product.

**Live site:** https://zaevlad.github.io/vpsfocus-faq/

## What questions it answers

229 questions in 18 categories:

| Category | Examples |
| --- | --- |
| General | What is vpsFocus, who is it for, what does it monitor, what gets installed on my server |
| Installation and first run | Requirements, pre-install check, updates, removal, adding the first site |
| Privacy, security and data | Where data is stored, what happens to SSH credentials, third-party services |
| Visitor analytics | Reports, sources, funnels, events, retention |
| Uptime, domains and certificates | Checks, SSL/domain expiry, maintenance windows |
| Public status pages | What is shown publicly and what never is |
| Server health and errors | CPU, memory, disk, 5xx/404 spikes, failed services |
| SEO audit and broken links | The 56 checks, crawls, CSV export |
| Speed and Core Web Vitals | PageSpeed, Core Web Vitals vs. SEO audit |
| Notifications, reports and calendar | Alerts, digests, schedules |
| AI crawlers, MCP and AI assistants | Tracking AI bots, read-only MCP access |
| Domain mail and Cloudflare | Mail records, Cloudflare integration |
| Plans and pricing | Free vs. paid, limits |
| Teams and agencies | Multiple clients, access, shared projects |
| Backup, export and migration | Moving data, exports |
| Website compliance | Cookies, consent, privacy requirements |
| Alternatives and comparisons | vs. APM tools and other analytics services |
| Troubleshooting and limits | Common failures and known limitations |

## How AI agents and tools can use it

Every view is generated from the same source, so answers never drift apart:

| URL (relative to the site root) | Format |
| --- | --- |
| `/` | Human-readable FAQ page |
| `/q/<slug>` | One page per question (with structured data) |
| `/llms.txt` | Index of all questions for LLMs |
| `/llms-full.txt` | Every question and answer as one Markdown file |
| `/faq.json` | Structured JSON |
| `/sitemap.xml`, `/robots.txt` | For search engines and crawlers |

## Editing content

All questions and answers live in a single file: [`src/data/faq.ts`](src/data/faq.ts). The page, `/q/<slug>`, `faq.json`, `llms-full.txt` and the sitemap are rendered from it, and `public/llms.txt` is regenerated by `scripts/generate-llms.mjs` during the build. Keep FAQ presentation separate from that file, and update `FAQ_UPDATED` whenever answers change.

## Development

Built with TanStack Start, React, Vite and Tailwind. Requires [Bun](https://bun.sh).

```sh
bun install
bun run dev          # local dev server
bun run test         # tests
bun run lint         # eslint
bun run build:pages  # static build for GitHub Pages (output in dist/client)
```

## Deployment

Pushing to `main` runs `.github/workflows/deploy.yml`: install, lint, test, build and deploy to GitHub Pages. In the repository settings, **Pages → Source** must be set to **GitHub Actions**.

If the repository is renamed or a custom domain is added, update the base path in `vite.config.pages.ts`, `src/lib/seo.ts`, `scripts/generate-sitemap.mjs`, `public/robots.txt` and `public/404.html`.
